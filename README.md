# Стоп-лист Coperto

Экран стоп-листа кухни: список меню смены, фильтры, постановка в стоп и снятие со стопа. Бэкенд — route handler’ы Next.js, данные в памяти процесса.

## Запуск

Нужны Node.js 20+ и npm.

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000). Задержка GET/POST 600 мс и случайные 500 (~20 %) намеренные: так видны скелетон, ошибка списка и откат оптимистики.

## Слои и граница сервер / клиент

`app/page.tsx` — серверный компонент: читает `searchParams` и отдаёт их в клиентский `StopList`. `app/layout.tsx` и `app/providers.tsx` — оболочка и `QueryClientProvider`. HTTP — `app/api/menu-items/**`: в `route.ts` задержка, валидация и ответы, в `store.ts` сид и in-memory на `globalThis`.

Клиентский экран — `features/stop-list`: хуки Query, URL-фильтры и Zustand живут в `model`, таблица и панель в `ui` получают только пропсы и колбэки. Домен меню — `entities/menu` (типы, Zod, HTTP-клиент). Примитивы UI — `shared/ui`; `shared` от `entities` не зависит.

```
app/                  RSC, провайдеры, route handlers
features/stop-list/   экран стоп-листа: ui + model
entities/menu/        типы, схемы, API меню
shared/               Button, Select, Badge, Toast, слоты срока
```

## Архитектурные решения

Фильтры живут только в URL (`router.push`), список — только в TanStack Query, панель и тосты — только в Zustand: один факт в одном месте, reload и «назад» работают без дубля кэша. Таблица и панель не знают про запросы: мутации с `cancelQueries` / `onMutate` / `onError` / `onSettled` сидят в хуках фичи, UI меняет строку сразу и откатывает её при ошибке. Одна Zod-схема `StopItemPayload` проверяет причину и срок и в форме (React Hook Form), и в `POST .../stop`. Слои ближе к FSD, чем к ориентиру `types/` + `server/` из ТЗ: домен меню отделён от операции стоп-листа, общее UI не импортирует сущность.

## In-memory на Vercel

Список хранится в памяти процесса, не в базе. На Vercel после простоя инстанса данные снова из сида — это ожидаемо для мока. В dev тот же массив переживает hot reload через `globalThis`.

## Допущения

- «Вернуть в продажу» — в панели, не кнопкой на строке: в таблице сверка стопа и срока, статус меняется после подтверждения.
- Бейдж на строке — «Стоп»; причина стопа только в панели.
- Нет `shop` / `status` в URL — все позиции; невалидный параметр уходит в GET как есть, сервер отвечает 400.
- Срок — «до конца смены» или слот 15 минут на 24 часа, без свободного ввода времени.

## Что доделал бы

- При нулевом остатке с этого экрана нельзя вернуть блюдо в продажу: нужен способ пополнить остаток или снять стоп отдельно.
- Когда срок стопа выходит, статус должен сам становиться «в продаже».
