# План: стоп-лист Coperto

---

## 1. Архитектура, приёмы, стек

### Три источника правды (без дублирования)

- **URL** — только фильтры `shop` и `status`. Reload и кнопка «назад» работают, потому что фильтры пишем через `router.push` (новая запись в истории).
- **TanStack Query** — единственный кэш меню. Ключи фабрикой `menuKeys.list(filters)`, оптимистика через `cancelQueries` / `onMutate` / `onError` / `onSettled` (`invalidateQueries`). У запроса списка `retry: false`.
- **Zustand** — только UI-хром: открыта ли панель, `selectedId`, тосты. Список позиций сюда не кладём.

**Обоснование решения.** Требование ТЗ плюс разделение по типу жизни данных: URL шарится и переживает reload, Query умеет оптимистику, Zustand — эфемерный UI. Один факт в одном месте, без рассинхрона.

### Граница сервер / клиент

- `app/layout.tsx` — оболочка: html, шрифты, провайдеры, фон.
- `app/page.tsx` — RSC: читает `searchParams`, рендерит клиентский экран `StopList`.
- Клиент (`StopList`): заголовок, фильтры, таблица, строки, панель, тосты. Здесь же хуки Query и запись фильтров в URL.
- `app/api/menu-items/**` — HTTP в `route.ts`, данные в `store.ts`.
- GET списка: задержка 600 мс, фильтры `shop` и `status`; нет параметра — все. Невалидное значение параметра — 400. Редкий 500 (~10%), чтобы было видно состояние ошибки. Пока первый запрос в `isPending` — скелетон таблицы.

**Обоснование решения.** Клиент/сервер — требование ТЗ. 600 мс — чтобы скелетон успели заметить. `retry: false` и инъекция 500 — экран ошибки списка показывается за одну задержку, «Повторить» делает повтор явно.

### Слои и папки (утверждено)

Импорты: `app/page` → `StopList`; `StopList` → `model` + ui фичи + `shared/ui`; `Filters`, `StopListTable`, `StopListItem`, `StopReasonPanel` → `shared/ui` и пропсы, без запросов и хуков Query; `model` → `entities/menu/api`; `entities/menu/api` → типы; `route.ts` → `store.ts` + `shared/lib` + типы из `entities/menu/model`.

```
app/
  layout.tsx, page.tsx, providers.tsx
  api/menu-items/route.ts              GET списка
  api/menu-items/store.ts              сид + in-memory на globalThis
  api/menu-items/[id]/stop/route.ts
  api/menu-items/[id]/resume/route.ts

features/stop-list/
  ui/     StopList, Filters, StopListTable, StopListItem, StopReasonPanel
  model/  ключи Query, хуки, URL-фильтры, Zustand (панель, тосты)

entities/menu/
  model/  типы: Shop, StopReason, MenuItem (в т.ч. updatedAt), StopItemPayload
  api/    getMenuItems, stopMenuItem, resumeMenuItem

shared/
  ui/     Button, Select, Badge, Toast
  lib/    Zod-схема StopItemPayload, схема query shop/status, validateUntil
```

**Обоснование решения.** Слои по смыслу FSD: домен меню (`entities`) отдельно от операции стоп-листа (`features`), общее UI и валидация — в `shared`. Таблица без запросов — требование ТЗ. Store рядом с API — колокация, три роута делят одну память процесса.

### Валидация

- Одна Zod-схема `StopItemPayload` и `validateUntil` в `shared/lib`. На клиенте форма панели — React Hook Form + тот же resolver.
- Клиент: на submit «В стоп-лист» / «Сохранить»; на blur — только если значение уже выбрано и оно невалидно. Пустой уход с поля ошибку не ставит.
- `POST .../stop` и правка стопа: та же схема в route handler до записи в `store`. Причина — одно из четырёх `StopReason`. Срок — `null` (до конца смены) либо ISO: в будущем, не дальше 24 часов, шаг 15 минут.
- `POST .../resume` при `stock === 0` — отказ.
- GET: Zod-схема query. Нет `shop` / `status` — все. Иначе только `kitchen` | `bar` | `pastry` и `available` | `stopped`; иное значение — 400 с текстом ошибки. Клиент показывает этот текст и «Повторить».

**Обоснование решения.** Требование ТЗ: одни правила на клиенте и на сервере. Сервер — источник истины. Невалидный URL не маскируется под полный список. Пустой blur без ошибки: иначе открыть панель «посмотреть» нельзя без красных полей; в ТЗ проверка и на потере фокуса.

### Стек

Next.js App Router, React, TypeScript strict, Tailwind, TanStack Query, Zustand, Zod, React Hook Form, Framer Motion, ESLint, Prettier.

**Обоснование решения.** Требование ТЗ.

### Дизайн (черновик, утверждаем по подпунктам)

#### Общие правила

- Ориентир ширины — десктоп 1280px. Вёрстка сжимается на узком экране без горизонтального скролла: колонки таблицы гибкие, длинные названия обрезаются с многоточием.
- Цвета — CSS-переменные в `shared/styles/tokens.css`, подключены в Tailwind `@theme`: фон `#F6F3EE`, текст `#171512`, вторичный `#6B645C`, поверхность `#FFFBF7`, граница `#E4DDD4`, ошибка `#B42318`, акцент `#C6462F`.
- Акцент — кнопки постановки в стоп и бейджи статуса «в стопе».
- Один шрифт на весь интерфейс: системный стек `ui-sans-serif, system-ui, sans-serif`.
- Иерархия размером и насыщенностью: заголовок страницы → лейблы → ошибки.
- Анимация Framer Motion: выезд правой панели, смена бейджа статуса у строки.

**Обоснование решения.** Палитра, ширина и системный шрифт — требование ТЗ. Токены в CSS + `@theme` — один источник цвета для утилит Tailwind.

#### Страница

- Заголовок «Стоп-лист» — в `StopList`, над фильтрами.
- Фича `StopList`: заголовок, фильтры, таблица, панель. Хуки списка и мутаций только здесь.
- Колонка (заголовок + фильтры + таблица): ширина до 1280px, по центру вьюпорта. Ширина колонки при открытой панели та же.
- Панель ~400px поверх правого края этой колонки: закрывает колонки «Статус» и «Срок». Слева остаются название, цех, остаток.

**Обоснование решения.** Панель поверх списка: сетка строк не перестраивается. Статус и срок в этот момент в карточке панели; в таблице остаются название, цех, остаток.

#### Фильтры

- Два независимых фильтра: цех и статус. Каждый — горизонтальная группа кнопок, в группе выбран ровно один вариант (поведение radio).
- Цех: Все / Кухня / Бар / Кондитерская. В URL: нет `shop` → все; иначе `kitchen` | `bar` | `pastry`.
- Статус: Все / В продаже / В стоп-листе. В URL: нет `status` → все; иначе `available` | `stopped`.
- Смена фильтра — `router.push`. «Все» убирает свой параметр из URL.
- Невалидный `shop` или `status` в URL уходит в GET как есть; сервер отвечает 400, клиент показывает ошибку списка. Фильтры остаются, выбор допустимого значения переписывает URL.
- Группы стоят под заголовком, в левой видимой части колонки: при открытой панели остаются целыми.
- Клавиатура: `role="radiogroup"`, стрелки и Space/Enter внутри группы.

**Обоснование решения.** Фильтры в URL — требование ТЗ (reload и «назад»). Пустой адрес = «все»: дефолт совпадает с `/`, ссылка на полный список короче. Radio-группы с «Все» — смена и сброс за один клик, состояние группы всегда явно.

#### Список

- Один компонент-таблица на общей подложке: шапка колонок + строки. `StopListTable` и `StopListItem` — презентация: только пропсы, без Query и API.
- Колонки слева направо: Название, Цех, Остаток, Статус, Срок. Шаблон: `minmax(12ch, 1fr) max-content max-content max-content max-content`. Название забирает свободное место и обрезается многоточием. `updatedAt` в таблице не показываем.
- Чередование фона строк (лёгкая зебра) для чтения по горизонтали.
- Загрузка: скелетон тех же колонок только при `isPending` первого GET (600 мс). Фоновый refetch после `invalidateQueries` (`isFetching`) скелетон не включает — на экране остаётся текущий кэш.
- Ошибка GET (400 невалидных фильтров или 500): текст с сервера и «Повторить» (`refetch`). Пустой список: пояснение в теле таблицы.
- Оптимистичное обновление меняет одну строку.

**Обоснование решения.** Выровненные колонки удобно сканировать на 12–15 позициях. Название разной длины забирает свободное место; цех, остаток, статус и срок — по ширине текста. Зебра держит взгляд на строке. Срок в списке — требование ТЗ. Скелетон только на первый запрос — список не мигает при инвалидации.

#### Блюдо (`StopListItem`)

- Заголовки колонок одним словом: Название, Цех, Остаток, Статус, Срок.
- Клик по строке открывает панель. Выбранная строка подсвечена. Строка в таб-порядке, Enter/Space открывают панель, `aria-selected` когда панель этой позиции открыта.
- В продаже: статус и срок пустые, строка обычным цветом.
- В стопе: вся строка приглушена (текст и фон); статус — «Стоп»; срок — «до конца смены» или время слота.
- Пока мутация этой строки в полёте: в статусе «Сохраняется».
- На строке нет кнопок. Клик всегда открывает панель.

**Обоснование решения.** Список — сверка: стоп и срок на строке (ТЗ). Причина в панели: она нужна при правке. «Вернуть в продажу» в панели: смена статуса только после подтверждения. Пустой статус в продаже: норма не подписываем.

#### Панель (`StopReasonPanel`)

- Правая панель ~400px поверх правого края колонки 1280px.
- Всегда одна шапка блюда: название, строка мета (`Цех · остаток N`), статус («В продаже» / «Стоп»).
- Ниже — одни и те же контролы причины и срока на React Hook Form (resolver — Zod-схема `StopItemPayload`). В стопе значения предзаполнены (правка). Мутации приходят колбэками из `StopList`.
- Причина — селект из map в `entities/menu`: закончились продукты, сломалось оборудование, вопросы к качеству, выведена из меню смены.
- Срок — список с прокруткой (scroll-snap, 3–4 видимые строки). Пункты: «До конца смены» (`until: null`) и слоты с шагом 15 минут от ближайшего будущего до `now + 24ч`, подписи «сегодня, 14:30» / «завтра, 09:00». В продаже значение после явного выбора; в стопе подставляются текущие причина и срок.
- В продаже: одна кнопка «В стоп-лист». Если причина или срок не выбраны — клик показывает ошибки под полями, запрос не уходит.
- В стопе: «Вернуть в продажу» и «Сохранить». «Сохранить» неактивна, пока причина и срок совпадают с сохранёнными. При `stock === 0` «Вернуть в продажу» неактивна, по наведению на обёртку — «Нельзя вернуть в продажу при нулевом остатке».
- Закрытие: крестик, клик вне панели, Escape. При открытии фокус внутрь панели (ловушка Tab), при закрытии — обратно на строку. `role="dialog"`, `aria-modal="true"`, `aria-labelledby` на название блюда.

**Обоснование решения.** Панель вместо только формы: в таблице имя обрезано, статус и срок под оверлеем. Снятие со стопа в той же панели (в ТЗ — без отдельной формы resume). Слот-список срока сам соблюдает шаг и 24 часа. «Сохранить» только при изменении — меньше пустых запросов.

#### Доступность

- Панель: Escape закрывает; диалог с `role="dialog"`, `aria-modal`, подписью названия; фокус не уходит на таблицу, пока панель открыта; после закрытия фокус на той же строке.
- Список слотов срока: `role="listbox"`, стрелки вверх/вниз, выбранный пункт `aria-selected`.
- Поля с ошибкой: `aria-invalid`, текст ошибки связан через `aria-describedby`.
- Кнопки и фильтры доступны с клавиатуры, видимый focus ring.
- Тост ошибки: `role="status"`.

**Обоснование решения.** Требование ТЗ: Esc, aria, работа с клавиатуры.

#### Пожелания для улучшения

- Сейчас при нулевом остатке блюдо нельзя вернуть в продажу с этого экрана. Нужен способ пополнить остаток или снять стоп.
- Когда срок стопа выходит, статус блюда должен сам становиться «в продаже».

#### Кнопки (`Button`)

- Варианты: акцент (стоп), основная/нейтральная (вернуть в продажу, повторить), ghost (закрыть).
- На время отправки: `disabled`, текст состояния («Сохраняем…») и спиннер.
- «Вернуть в продажу» в панели — сразу POST resume.

#### Поля (причина и срок)

- Причина — `Select` из map в `entities/menu`, четыре значения, `Controller` / регистрация в React Hook Form. Пустое значение на сервер не уходит.
- Срок — прокручиваемый список слотов (scroll-snap), то же поле формы. Пункты: «До конца смены» и шаги 15 минут на 24 часа.
- Оба поля с лейблом. Уход с пустого поля ошибку не ставит. После «В стоп-лист» / «Сохранить»: красная обводка и текст под каждым незаполненным или невалидным полем (`aria-invalid`, `aria-describedby`).

**Обоснование решения.** Вид ошибки — требование ТЗ. React Hook Form держит одну Zod-схему на клиенте. Пустой blur без ошибки: человек мог открыть список и ничего не выбирать. Слот-список срока сам соблюдает шаг и окно 24 часа; сервер проверяет ту же схему.

#### Тосты

- Очередь в Zustand. Показ: ошибка сервера после отката оптимистики (stop / resume / сохранить).
- Сверху справа, автоскрытие, закрытие вручную. Текст — сообщение с сервера.

**Обоснование решения.** Требование ТЗ: ошибка мутации видна, строка уже откатилась. Поля остаются с подписями у контролов.

#### Бейдж (`Badge`)

- В колонке «Статус»: «Стоп» (акцент `#C6462F`) и «Сохраняется». В продаже ячейка пустая.

**Обоснование решения.** Метка «Стоп» и колонка срока закрывают требование ТЗ показать стоп и срок на строке. Причина стопа — в панели: на строке четвёртый текст мешал бы сверке.
